# 阶段规划与一期交付标准

> 更新日期：2026-10-15。
>
> 本文用「能把哪件已经发生过的事在系统里走完」来判断一期，而不是用功能条数。月份不是排期。调研报告里的甘特图是教学示意，本文不沿用那些起止月。
>
> 课程叙事说2020年上半年门户已经上线，但代工厂没有接全，历史订单没有迁入。那是背景，不是本仓库的交付证明。验收数据见【待确认-34】。

---

## 一、两段范围

| 段 | 对应的业务时点 | 完成时供应商能做什么 | 明确仍不做 |
| --- | --- | --- | --- |
| 一期，交付协同 | 阶段4，预警用10天 | 看到ERP已审核的采购订单，24小时内确认或提交交期建议；按节点反馈齐套；提交带箱码的发货和预约；看到实收结果 | 对账、开票、寻源、商城、排产、直接指挥WMS收货 |
| 阶段5增强 | 直播脉冲和上市审计，预警默认7天 | 在一期之上看到半成品备料进度和快收标记；完成对账、开票申请、税票登记和红字确认记录 | 应付、付款、凭证；绩效自动改配额 |

两段的模块边界以[项目背景](2.强盛科技SRM项目的背景信息.md)为准。这里只加「怎样算走通」。

历史未结订单如何出现在门户里，见【待确认-32】。没有这条，下面的场景只能用新订单演示，不能声称旧账已经可追溯。

## 二、一期走通的四个场景

场景都来自阶段背景。通过标准里的天数、箱数和抽查笔数，除了背景已经写死的24小时和10天，其余见【待确认-34】。

### 2.1 新品首发前的缺料要提前看见

对应2020年下半年那次「交货前一周才说缺料」。

```plain
ERP 下发已审核采购订单
    → 供应商在24小时内确认，或提交交期建议
    → 关键物料节点在距交期前10天仍未完成
    → 采购看得到预警，订单数量和价格没有被门户改掉
```

交期建议被接受之后，如果ERP还没有调整承诺交期，页面上必须看得出「建议已接受、ERP尚未改期」，不能显示成订单已经改完。

### 2.2 从一个外箱追回工厂和批次

对应充电宝过热、纸单追不回批次。

```plain
扫描一枚有效箱码
    → 查到发货单、采购订单、供应商、SKU、供应商批号和数量
    → 若 ERP 已有入库，能看到对应的采购入库单号
```

供应商批号能否写进ERP库存批次，见[待对齐事项A12](11.待对齐事项.md)。这个场景在一期只要求「码能查回单据」，不要求库存批次已经贯穿。作废箱码扫出来必须是作废，不能当成可收货。

### 2.3 一张订单分两次到货，第二次没收齐

对应ERP已经定稿的分批、缺量和零收。

```plain
一张采购订单分两张发货单
    → 第一张按通知数量收完，生成采购入库单
    → 第二张实收少于通知，ERP 按缺量留下还可下推的数量
    → 若第二张实收为 0，ERP 取消该通知，门户不出现零数量入库单
```

门户不能出现第二张收货指令。仓库执行的仍是ERP采购收货通知单。若接口还不能由发货单生成通知单，这个场景要标明「通知单由采购代录」，不能演示成门户已经指挥仓库。

### 2.4 未上线的工厂由采购代录

对应上线初期工厂没有接全。

```plain
采购代供应商确认订单并登记发货
    → 日志里有代录人、时间和依据
    → 数量、关闭、超量校验和供应商自己操作相同
```

代录不能成为改价入口。

## 三、阶段5再走通的两个场景

这两件不作为一期完成的条件。

### 3.1 直播爆单后的短周期交付

对应2024年抖音3万单、现货1万台、常规周期20天压到3至5天。

门户要能看到：哪张采购订单是在半成品备料之后追加的，供应商反馈的组装完成量，以及这批货是否按源头贴码发往指定月台。备料在ERP用什么单据，见【待确认-10】。单据没定之前，这个场景不能用一个自造的「备料单」类型演示完就当成规则。

预警在这一段用7天，不用10天回写阶段4的订单。

### 3.2 抽一张入库单能追到税票

对应2024年尽调要看到采购单和供应商发票。

```plain
指定一张已审核采购入库单
    → 追到采购收货通知单、发货单、箱码、采购订单
    → 若已对账，追到对账单和开票申请
    → 若已登记税票，看到20位发票号码
    → 银行流水和凭证从金蝶继续往下，不在门户里做一份假的付款
```

红字如果发生，要能区分「购买方尚未确认用途，供应商直接开红字」和「已经确认，先有红字确认单，72小时未确认则作废」。操作发生在税务平台还是接口，见【待确认-08】。

## 四、怎样还不叫完成

| 现象 | 为什么不算完成 |
| --- | --- |
| 供应商只能在微信里回复，门户里没有确认记录 | 一期要的就是留下确认，而不是再做一个通知页面 |
| 发货单直接让仓库记账，ERP没有采购收货通知单 | 和ERP定稿冲突，见[待对齐事项A02](11.待对齐事项.md) |
| 箱码打印了，仓库扫不出来 | 码制未和实际收货端对齐，见【待确认-16】 |
| 对账单上改了数量才和供应商一致 | 违反结果单不在对账里更正的规则 |
| 参股厂不经确认就显示已接单 | 同一套规则被绕开 |
| 演示数据能走通，但外部接口没有联调记录 | 演示只证明流程表达，不证明仓库和金蝶已经接通 |

一期的判断场景走完，也不等于200多家都已上线。3家参股厂先接入，是建议的顺序，不是验收时必须已经签完的实施计划。
