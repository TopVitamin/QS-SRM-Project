## 一、订单、交期和收货以哪边为准

| 事项 | 规则 | 依据 |
| --- | --- | --- |
| 采购订单 | 源头在SRM。采购员创建并审核，审核通过后推送ERP。一张SRM订单对应一张ERP订单，不合并、不拆分。ERP侧只读。变更只能在SRM发起 | 本次决定。ERP旧文见[待对齐事项A01](11.待对齐事项.md)，ERP文档后续另行对齐 |
| 推送 | 同一张SRM订单不得在ERP变成第二张。失败时保留SRM订单，记下失败，重试同一笔。核对单号、供应商、行、数量、价格、交期、关闭状态 | [待对齐事项A02](11.待对齐事项.md)。次数和频率见【待确认-06】。单号见【待确认-05】 |
| 承诺交期 | 供应商可以多次提建议。采购在SRM接受后，变更从SRM发起并再次推送。ERP不单独改交期 | 能改哪些字段见【待确认-03】。绩效用第一次还是最后一次，见【待确认-33】 |
| 采购收货通知单 | 执行指令在ERP。发货单推动ERP生成通知单，再由ERP下发WMS。一次通知只接收一次最终结果，允许缺量，拒绝超量，零收按取消 | ERP执行规则仍然有效。旧文「采购代录」见[待对齐事项A03](11.待对齐事项.md) |
| 采购入库单、采退出库单 | 实际结果和推送金蝶的依据。经ERP回传后，SRM只读。对账取这两类已审核单据 | [待对齐事项A06](11.待对齐事项.md)、[A07](11.待对齐事项.md) |
| 供应商 | 编码和准入资格的源头不在门户。阶段4按ERP维护；阶段5是否上移，见【待确认-13】 | ERP主数据口径 |
| 供货关系 | ERP不建。门户不能用它限制SRM下单 | [待对齐事项A09](11.待对齐事项.md) |

关闭和取消的发起方还没有选定，见【待确认-04】，并见[待对齐事项A05](11.待对齐事项.md)。在【待确认-04】有结论之前，不把「ERP自动关单」或「SRM自动关单」写成已经生效。ERP旧文里已经写明、本次只改发起方、不改后果的，先记在这里供对照：

- 取消是整张采购订单不再执行。已有实际入库的，不能取消整单。
- 承诺交期过后第2个自然日的北京时间0:00自动关闭。全部收足不会自动关单。关闭后不可反关单。
- 关闭后，已经生成的收货通知是否继续执行，ERP旧文写「继续」。是否仍适用，见【待确认-04】。
- 一期不设行关闭、行取消。超量回传由ERP拒绝。见[待对齐事项A08](11.待对齐事项.md)。

## 二、数量怎么卡

这些数量规则约束的是收货执行，不因为订单改在SRM创建而放开。

| 规则 | 怎么用 |
| --- | --- |
| 可下推数量以ERP为准 | 发货单保存时，本次数量不得大于ERP该行还可下推的数量。不设超收容差 |
| 分批 | 一张采购订单可以分多次发货。每一批发货对应ERP的一张采购收货通知单，一次最终回传。是否允许一张发货单跨多张订单，见【待确认-07】 |
| 缺量 | 实收少于通知时，按ERP缺量回补可下推额度。门户不把「少收」记成自己的库存差异 |
| 零收 | ERP取消该通知，不生成零数量入库单。门户展示为本次发货被取消，额度回到订单 |
| 超量回传 | ERP直接拒绝。多出的实物如何处理，见【待确认-10】。门户不能先让供应商把超量发出去 |
| 对账取数 | 用ERP已审核的采购入库单、采退出库单，不用发货单上的数量 |
| 箱码 | 同一发货行下，箱码数量之和等于该行发货数量 |
| 退货补货 | 走ERP采购退货链。需要新采购订单时在SRM创建。是否占用原订单额度，见【待确认-10】 |

## 三、时限：背景已经写明的，和还不能当规则的

| 事项 | 已经写明的 | 还不能当成规则的 |
| --- | --- | --- |
| 接单 | 订单发出后24小时内确认交期 | 超时是否自动接受、能否按供应商改时限、未确认能否发货、能否带条件接受，见【待确认-19】 |
| 交付预警 | 阶段4：距交期前10天。阶段5：收紧为7天 | 7天从哪一天开始对哪一类供应商生效，背景只说「按协同成熟度」。实际及时率见【待确认-30】 |
| 进度 | 分阶段反馈齐套 | 节点清单见【待确认-20】。未列出的节点，不能要求供应商必报 |

在【待确认-19】关闭之前，设计上不能采用「超时自动视为已确认」，也不能把带条件接受写成已经允许。自动确认会把未表态写成供应商已经承诺，和上市尽调要的证据相反。

预约是否人工确认、爽约宽限，见【待确认-24】。

推送到ERP的重试次数和间隔没有写明，见【待确认-06】。不采用ERP仓库推送「最多3次」。

## 四、谁能看见、谁能代办

组织架构不映射角色。下面是权限原则。角色名称没有定，见【待确认-34】。

| 原则 | 说明 |
| --- | --- |
| 供应商隔离 | 一家供应商只能看见自己的订单、发货、对账和税票 |
| 参股厂 | 可以用更紧的预警和单独看板，不能看见其他供应商的价格和份额 |
| 代录 | 只用于尚未上线的供应商。代录人、时间和依据必填。代录不能变成在ERP另建订单，也不能改价 |
| 审核强度 | ERP一期允许本人审核本人创建的数据。那是ERP的权限口径，不自动变成SRM的规则。在没有新的规定之前，SRM不建设多级审批和会签，也不把「必须另一人审核」写成已经生效 |
| 分管 | 采购员是否只看自己负责的供应商，见【待确认-34】 |
| 子账号 | 供应商主账号能否自己建子账号，见【待确认-34】。无论谁建，数据范围仍然是本公司 |

## 五、留痕

SRM上的创建、审核、推送、失败、重试、确认、撤回、变更、发货、代录、对账和发票登记，必须记下操作者、时间、对象和前后值。

ERP一期不把完整操作日志列为必做。门户不能照抄这条，也不回头扩大ERP的一期范围，见[待对齐事项A10](11.待对齐事项.md)。

附件是门户自己的能力。资质、发票文件、代录依据都放在这里。不要求ERP一期先提供通用附件。

## 六、对账和开票先守住的边界

这些边界来自ERP的结果单规则，不来自竞品的对账单状态：

- 对账基准只能是ERP已审核的采购入库单和采退出库单。
- 数量和单价不能在对账单上改。差异退回采购处理。处理如果需要新订单或变更，从SRM发起，见[待对齐事项A07](11.待对齐事项.md)。
- 阶段5的目标顺序是：对账确认之后才进入开票。这不是ERP里已经有的单据规则，容差数值见【待确认-17】。
- 谁发起对账，见【待确认-16】。两种发起方式如果同时存在，取值规则仍然是上一行，不因为供应商发起就允许改数。

## 七、容易写拧的限制

| 可以做 | 不能做成 |
| --- | --- |
| 在SRM创建并审核采购订单，审核后推送ERP | 在ERP再录一张订单，或把ERP旧文里的「人工测算后建单」当成现行规则 |
| 展示ERP的缺量、零收取消和入库结果 | 在门户重做一套订单状态机去覆盖ERP的入库结果 |
| 采集供应商批号 | 宣称ERP库存批次规则已经定稿，见[待对齐事项A13](11.待对齐事项.md) |
| 关键协同日志必做 | 回头把ERP一期改成「日志必做」 |

【待确认-01】至【待确认-45】里没有结论的条目，不能在详细设计里被补成「行业通常如此」。
