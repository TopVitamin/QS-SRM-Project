# 强盛SRM全局业务规则与约束

> 更新日期：2026-10-15。
>
> 本文集中写跨模块的硬规则：哪些跟ERP走，哪些是阶段背景里已经写明的协同时限，哪些只是建议、还不能当规则。项目范围见[项目背景](2.强盛科技SRM项目的背景信息.md)，系统边界见[上下游链路](3.强盛SRM的定义和上下游链路.md)。
>
> 不在本文里做的事：状态枚举、按钮条件、字段必填。那些放在后续目录。本文没有写到的处理方式，不存在默认方案。

## 一、对象归谁

| 对象 | 规则 | 依据 |
| --- | --- | --- |
| 采购订单 | 源头在ERP。门户只有协同视图。已审核后不能改数量和价格，不能做变更单 | ERP《4》§3.2、[待对齐事项A01](11.待对齐事项.md) |
| 承诺交期 | 供应商可以多次提建议。采购接受后，由ERP调整交期。调整会改变「承诺交期过后T+2自然日」的自动关闭日 | ERP《5》§5.2。绩效用第一次还是最后一次，见【待确认-29】 |
| 采购收货通知单 | 执行指令在ERP。一次通知只接收一次最终结果，允许缺量，拒绝超量，零收按取消 | ERP《5》§5.3、§8.2 |
| 采购入库单、采退出库单 | 实际结果和推送金蝶的依据。门户只读，对账取这两类已审核单据 | ERP《3》§3.7、[待对齐事项A04](11.待对齐事项.md) |
| 发货单、箱码、预约 | 门户自有的协同记录。不增加库存，不代替通知单 | 本文与[单据目录](5.强盛SRM的单据目录与分层.md) |
| 供应商 | 编码和准入资格的源头不在门户。阶段4按ERP维护；阶段5是否上移，见【待确认-07】 | ERP《2》主数据节 |
| 供货关系 | ERP不建。门户不能用它限制下单 | [待对齐事项A07](11.待对齐事项.md) |

关闭和取消沿用ERP，不在门户复述成另一套：

- 取消是整张采购订单不再执行。已有实际入库的，不能取消整单。
- 关闭是不再安排剩余采购。已有通知继续执行，不能反关单，也不能对已关闭订单再新建发货。
- 采购订单在承诺交期过后第2个自然日的北京时间0:00自动关闭。全部收足不会自动关单。
- 一期不设行关闭、行取消。见[待对齐事项A06](11.待对齐事项.md)。

## 二、数量

| 规则 | 门户怎么执行 |
| --- | --- |
| 可下推数量以ERP为准 | 发货单保存时，本次数量不得大于ERP该行还可下推的数量。不设超收容差 |
| 分批 | 一张采购订单可以分多次发货。每一批发货对应ERP的一张采购收货通知单，一次最终回传 |
| 缺量 | 实收少于通知时，按ERP缺量回补可下推额度。门户不把「少收」记成自己的库存差异 |
| 零收 | ERP取消该通知，不生成零数量入库单。门户展示为本次发货被取消，额度回到订单 |
| 超量回传 | ERP直接拒绝。多出的实物如何处理，见【待确认-26】。门户不能先让供应商把超量发出去 |
| 对账数量 | 取已审核入库和采退，不取发货单上的预约数量 |
| 退货补货 | 走ERP采购退货链。是否占用原订单额度，见【待确认-26】 |

箱码上的数量之和应当等于该发货行的数量。这是打印约束，不是库存账。库存不按箱记。

## 三、时限和预警

阶段背景已经写明的，只有下面两条。其余时限都还没有公司自己的数。

| 事项 | 已经写明的 | 还没有写明的 |
| --- | --- | --- |
| 接单 | 订单下发后24小时内确认交期 | 超时是否自动接受、能否按供应商改时限、未确认能否发货，见【待确认-18】。带条件接受见【待确认-19】 |
| 交付预警 | 阶段4：距交期前10天。阶段5：收紧为7天 | 7天从哪一天开始对哪一类供应商生效，背景只说「按协同成熟度」。实际及时率见【待确认-06】 |

在【待确认-18】关闭之前，设计上不能采用「超时自动视为已确认」。自动确认会把未表态写成供应商已经承诺，和上市尽调要的证据相反。这是限制，不是已经拍板的替代规则。

国内有的项目要求必须先确认才能发货。强盛背景只要求24小时内确认，没有写未确认能否发货。两者不要合成一条。

预约是否人工确认、爽约宽限，见【待确认-17】。

## 四、代录、隔离和审核

组织架构不映射角色。下面是权限原则。角色名称没有定，见【待确认-30】。

| 原则 | 说明 |
| --- | --- |
| 供应商数据隔离 | 供应商用户只能访问本供应商的订单、价格、交期和发票。参股厂即使有单独看板，也不能看其他供应商的价格和份额 |
| 企业侧按职责授权 | 采购跟单、计划、品质、仓储、财务、系统管理是职责，不是已经建好的角色。计划默认只读。仓储按仓。财务看对账和税票，不在门户里做付款 |
| 代录 | 供应商尚未上线时，采购可以代为确认和登记发货。记录代录人、时间和依据。代录不降低数量、价格和关闭规则 |
| 审核强度 | ERP一期是RBAC、单级审核，允许本人审核本人创建的数据，权限不能绕过数量和状态校验。门户是否完全沿用，背景没有单独规定。在没有新的规定之前，不建设多级审批和会签 |
| 分管 | 采购员是否只看自己负责的供应商，见【待确认-30】 |
| 子账号 | 供应商主账号能否自己建子账号，见【待确认-30】。无论谁建，数据范围仍然是本公司 |

金蝶供应商协同的公开手册写的是：供应商用户由企业统一创建，角色由企业授权，查询只显示该供应商的数据。见[金蝶云·星空供应商协同](https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%BE%9B%E5%BA%94%E5%95%86%E5%8D%8F%E5%90%8C)。这是对照，不是强盛已经选用金蝶门户。

## 五、留痕

ERP一期不把完整操作日志列为必做。门户不能照抄这条，见[待对齐事项A08](11.待对齐事项.md)。

必须留下的动作：接单确认和拒绝、交期建议的提交和接受驳回、发货单的提交和取消、箱码作废、预约的确认和改约、代录、对账确认和差异、开票申请和税票登记、红字确认过程。每条至少有操作者、时间、对象、前后值。代录还要有依据来源。

后台直接改数如果发生，必须另有记录。不能靠改数据库把确认时间补齐。

附件是门户自己的能力。资质、发票文件、代录依据都放在这里。不要求ERP一期先提供通用附件。

## 六、对账和发票的硬边界

这些边界来自ERP，不来自竞品的对账单状态：

- 对账基准只能是ERP已审核的采购入库单和采退出库单。
- 数量和单价不能在对账单上改。差异退回采购，在ERP处理。
- 阶段5的目标顺序是：对账确认之后才进入开票。这不是ERP里已经有的单据规则，容差数值见【待确认-23】。
- 谁发起对账，见【待确认-22】。两种发起方式如果同时存在，取值规则仍然是上一行，不因为供应商发起就允许改数。
- 门户不生成应付，不发起付款。预付继续线下。
- 已确认的对账单不因下一期退货而被改写。下一期退货进下一期对账。

数电票、红字确认单和三单匹配的法规要求见[合规与审计要求](8.合规与审计要求.md)。

## 七、容易和ERP搅在一起的限制

| 门户要守住的 | 不要因此扩进门户 |
| --- | --- |
| 展示ERP的关闭、缺量、零收取消 | 不在门户重做一套订单状态机去覆盖ERP |
| 采集供应商批号 | 不宣称ERP库存批次规则已经定稿，见[待对齐事项A12](11.待对齐事项.md) |
| 关键协同日志必做 | 不回头把ERP一期改成「日志必做」 |
| 箱码供仓库识别 | 不建箱库存，不执行FIFO |
| 参股厂用同一套单据 | 不因为参股就免确认、免对账或看到别人的价格 |

【待确认-12】至【待确认-36】里没有结论的条目，不能在详细设计里被补成「行业通常如此」。
