# 强盛SRM的单据目录与分层

> 更新日期：2026-10-15。
>
> 本文只回答两件事：门户里有哪些业务对象，它们落在ERP三层模型的哪一层。状态有哪些取值、谁可以点哪个按钮、字段如何校验，都放在后续的产品设计里。本文不设状态机。
>
> ERP三层的权威说明是[《5.强盛ERP的单据分层设计》](https://github.com/TopVitamin/QS-ERP-Project/blob/main/01-全局背景信息/5.强盛ERP的单据分层设计.md)。门户不另创一层库存结果。

---

## 一、为什么要挂到ERP的三层上

ERP已经把采购拆成三件不同的事：

| ERP层级 | 回答什么 | 采购链上的单据 |
| --- | --- | --- |
| 业务安排 | 一共要买多少、价格是什么、是否还继续办 | 采购订单 |
| 执行指令 | 这一批交给仓库收多少 | 采购收货通知单 |
| 实际结果 | 实际收进或退出多少 | 采购入库单、采退出库单 |

如果门户再做一张「供应商订单」或一张「直接让WMS收货的ASN」，同一批货就会有两张指令。所以门户的对象只允许两类：

1. **协同视图。** ERP单据的只读投影，加上供应商的回复。回复不改ERP的数量和价格。
2. **协同记录。** 门户自己保存的过程，例如交期建议、发货预告、箱码、预约、对账和税票。它们要么推动ERP去生成已有的通知单，要么留在门户供金蝶使用，但不成为第三套库存单据。

## 二、对象目录

「段」沿用[项目背景](2.强盛科技SRM项目的背景信息.md)：第一段是交付协同，第二段是阶段5的对账和开票。标了待确认的，目录里先留名字，不表示已经纳入本期。

| 对象 | 段 | 相对ERP的位置 | 谁产生 | 结果落在哪 |
| --- | --- | --- | --- | --- |
| 采购订单协同视图 | 第一段 | 第一层的只读投影 | ERP下发 | 不回写数量和价格。关闭、取消跟随ERP |
| 接单确认记录 | 第一段 | 附在采购订单上 | 供应商或代录的采购 | 留在门户。不生成ERP单据 |
| 交期建议 | 第一段 | 附在采购订单上 | 供应商提出，采购接受或驳回 | 接受后由ERP调整承诺交期。见[待对齐事项A01](11.待对齐事项.md) |
| 齐套与进度记录 | 第一段 | 不进入ERP单据层 | 供应商填写，品质可复核 | 只在门户。不是BOM，也不是入库 |
| 发货单 | 第一段 | 第二层的来源，不是第二层本身 | 供应商或代录 | 目标是生成ERP采购收货通知单。接口未通时，采购仍代录通知单 |
| 箱码 | 第一段 | 发货单下面的物流单元 | 门户生成，供应商打印 | 不建库存。作废后不能再收 |
| 预约送货 | 第一段 | 附在发货上 | 供应商提交，仓侧是否确认见【待确认-17】 | 不驱动收货过账 |
| 收货结果视图 | 第一段 | 第二层和第三层的只读投影 | ERP、仓库回传后由ERP生成 | 门户不改实收 |
| 退货协同视图 | 第一段 | 采购退货三层的只读投影 | ERP | 供应商确认和跟踪。补货、扣款不在门户决定 |
| 交付预警 | 第一段 | 不进入ERP单据层 | 系统按交期和节点生成 | 只提醒 |
| 对账单 | 第二段 | 不进入ERP单据层 | 取ERP已审核入库和采退 | 双方确认凭证。不生成应付 |
| 开票申请 | 第二段 | 不进入ERP单据层 | 从已确认的对账生成 | 告诉供应商应开金额和税额。不是税票 |
| 税票登记 | 第二段 | 不进入ERP单据层 | 供应商上传数电票 | 预校验后再交给金蝶。见【待确认-08】 |
| 红字确认单协同 | 第二段 | 不进入ERP单据层 | 记录税务规则要求的确认过程 | 红字发票本身在税务平台开具。见[合规要求](8.合规与审计要求.md) |
| 供应商用户 | 第一段 | 不是ERP单据 | 企业侧开通 | 只控制门户登录和数据范围 |
| 操作日志 | 第一段 | 不是业务单据 | 系统写入 | 不参与对账 |

下面这些名字在调研里出现过，强盛自己的资料没有要求本期一定要有，不放进上表的建设范围：

| 名字 | 为什么先不列入 |
| --- | --- |
| 委外供料、组件消耗 | 强盛是否把电芯等物料直采后再发给工厂，见【待确认-11】 |
| 费用单 | 索赔和运费是否在门户确认，以及记入金蝶哪张单据，见【待确认-27】 |
| 样品准入、询报价 | 见【待确认-31】。成品价格在ERP的价格管理 |
| 供货范围 | 即使以后记录，也不能限制ERP下单。见[待对齐事项A07](11.待对齐事项.md)、【待确认-36】 |
| 驻厂验货记录 | 阶段4写了驻厂QC按节点抽检，但记录放在门户还是品质系统，见【待确认-24】 |
| 质量异常 | 不合格要能追溯。一期是否单独立单，还是先附在收货结果上，没有定论。检验系统见【待确认-25】 |

## 三、和ERP单据怎么配对

| 门户对象 | ERP单据 | 配对规则 |
| --- | --- | --- |
| 采购订单协同视图 | 采购订单，前缀CGDD | 一张视图对应一张ERP订单。门户不另编一个「供应商订单号」当作业务主键 |
| 交期建议 | 采购订单的承诺交期 | 多条建议可以并存。只有ERP已经执行的那次调整，才是当前承诺交期 |
| 发货单 | 采购收货通知单，前缀CGSHTZ | 目标是一张发货单生成一张通知单，并回填通知单号。生成前，通知单仍可能由采购代录，两边要用来源关系对上，避免同一批货两张通知 |
| 发货单行 | 采购订单行 | 一行订单可以分多次发货。一张发货单是否允许跨订单，见【待确认-20】。未确认前按「一单、一仓」设计，以免和ERP通知单的单头来源冲突 |
| 收货结果视图 | 采购收货通知单和采购入库单，前缀CGRK | ERP一次通知只有一个最终结果，不存在「部分收货」这种通知状态。实收为0时通知取消，没有入库单 |
| 退货协同视图 | 采购退货单、采退发货通知单、采退出库单 | 只跟踪，不在门户另做退货入库 |
| 对账单行 | 采购入库单、采退出库单 | 不取发货数量。订单和通知单本身不对账 |
| 开票申请、税票 | 无对应ERP单据 | 通过入库单、采退出库单的单号向上追到通知单、发货单和采购订单 |

采购退货的前缀以ERP对照表为准：采购退货单CGTH，采退发货通知单CTFHTZ，采退出库单CTCK。见[ERP编码规则](https://github.com/TopVitamin/QS-ERP-Project/blob/main/01-全局背景信息/6.强盛ERP的编码规则和通用字段规则.md)。

## 四、追溯链要能串起来

阶段5要求抽到一笔入库时，能往前看到采购单，往后看到发票和凭证。门户负责补上供应商侧的那几环。目标链条是：

```plain
税票 / 红字确认记录
    → 开票申请
    → 对账单
    → 采购入库单或采退出库单
    → 采购收货通知单
    → 发货单和箱码
    → 采购订单
```

准入核验和同SKU的价格对比，是上市问询里常见的证据。强盛有没有这些记录、放不放在门户，见【待确认-28】【待确认-31】。没有记录时，不能在链条上画一个空节点假装已经留痕。

银行流水和凭证在金蝶，门户不复制一份资金账。

## 五、本文故意不写的内容

- 每张单据的状态名称、允许的跳转和并发。
- 表头表体字段、必填和默认值。
- 接口字段名、重试次数和错误码。
- 页面上按钮的位置。

后续目录如果给发货单设计状态，必须同时满足本文的分层：发货单的任何状态都不能表示「仓库已经按门户指令收货」。收货是否完成，只看ERP通知单和入库单。
