# 强盛SRM的单据目录与分层

> 更新日期：2026-10-15。
>
> 本文只回答两件事：门户里有哪些业务对象，它们落在哪一层。状态有哪些取值、谁可以点哪个按钮、字段如何校验，都放在后续的产品设计里。本文不设状态机。
>
> ERP三层的说明见[《5.强盛ERP的单据分层设计》](https://github.com/TopVitamin/QS-ERP-Project/blob/main/01-全局背景信息/5.强盛ERP的单据分层设计.md)。门户不另创一层库存结果。采购订单的源头已改在SRM，ERP那篇里「代录收货通知」的句子尚未改，见[待对齐事项A03](11.待对齐事项.md)。

---

## 一、三层怎么分

采购仍拆成三件不同的事。变的是第一层在哪边创建。

| 层级 | 回答什么 | 落在哪 |
| --- | --- | --- |
| 业务安排 | 一共要买多少、价格是什么、是否还继续办 | SRM采购订单。审核后推送，ERP只读持有副本 |
| 执行指令 | 这一批交给仓库收多少 | ERP采购收货通知单。由ERP下发给WMS |
| 实际结果 | 实际收进或退出多少 | ERP采购入库单、采退出库单。回传SRM只读 |

如果再做一张「另一份采购合同」，或者让发货单直接指挥WMS收货，同一批货就会有两张指令。所以门户的对象只允许两类：

1. **源头单据。** SRM采购订单。ERP持有的是只读副本，不是第二张合同。
2. **协同记录。** 接单确认、交期建议、发货预告、箱码、预约、对账和税票。发货单推动ERP去生成已有的通知单。对账和税票留在门户供金蝶使用，不成为第三套库存单据。

## 二、对象目录

「段」沿用[项目背景](2.强盛科技SRM项目的背景信息.md)：第一段是交付协同，第二段是阶段5的对账和开票。标了待确认的，目录里先留名字，不表示已经纳入本期。

| 对象 | 段 | 落在哪一层 | 谁产生 | 结果落在哪 |
| --- | --- | --- | --- | --- |
| SRM采购订单 | 第一段 | 第一层的源头单据 | 采购员在SRM创建并审核 | 推送后ERP只读持有。不在ERP另建 |
| 接单确认记录 | 第一段 | 附在SRM采购订单上 | 供应商，或代录的采购 | 留在SRM。是否随推送一起到达ERP，见【待确认-02】 |
| 交期建议 | 第一段 | 附在SRM采购订单上 | 供应商提出，采购在SRM接受或驳回 | 接受后的变更从SRM发起并推送。字段范围见【待确认-03】 |
| 齐套与进度记录 | 第一段 | 不进入ERP单据层 | 供应商填写，品质可复核 | 只在门户。不是BOM，也不是入库 |
| 发货单 | 第一段 | 第二层的来源，不是第二层本身 | 供应商或代录 | 推动ERP生成采购收货通知单。见[待对齐事项A03](11.待对齐事项.md) |
| 箱码 | 第一段 | 发货单下面的物流单元 | 门户生成，供应商打印 | 不建库存。作废后不能再收 |
| 预约送货 | 第一段 | 附在发货上 | 供应商提交，仓侧是否确认见【待确认-24】 | 不驱动收货过账 |
| 收货结果视图 | 第一段 | 第二层和第三层的只读投影 | ERP按WMS回传生成采购入库单后回传 | 门户不改实收，也不直接读WMS库存 |
| 退货协同视图 | 第一段 | 采购退货三层的只读投影 | ERP | 供应商确认和跟踪。补货、扣款不在门户决定 |
| 交付预警 | 第一段 | 不进入ERP单据层 | 系统按交期和节点生成 | 只提醒 |
| 对账单 | 第二段 | 不进入ERP单据层 | 取ERP已审核入库和采退 | 双方确认凭证。不生成应付 |
| 开票申请 | 第二段 | 不进入ERP单据层 | 从已确认的对账生成 | 告诉供应商应开金额和税额。不是税票 |
| 税票登记 | 第二段 | 不进入ERP单据层 | 供应商上传数电票 | 预校验后再交给金蝶。见【待确认-14】 |
| 红字确认单协同 | 第二段 | 不进入ERP单据层 | 记录税务规则要求的确认过程 | 红字发票本身在税务平台开具。见[合规要求](8.合规与审计要求.md) |
| 供应商用户 | 第一段 | 不是ERP单据 | 企业侧开通 | 只控制门户登录和数据范围 |
| 操作日志 | 第一段 | 不是业务单据 | 系统写入 | 不参与对账 |

下面这些名字在调研里出现过，强盛自己的资料没有要求本期一定要有，不放进上表的建设范围：

| 名字 | 为什么先不列入 |
| --- | --- |
| 采购申请、采购计划 | 来源未定，见【待确认-01】。未定之前不单列单据 |
| 委外供料、组件消耗 | 强盛是否把电芯等物料直采后再发给工厂，见【待确认-12】 |
| 费用单 | 索赔和运费是否在门户确认，以及记入金蝶哪张单据，见【待确认-31】 |
| 样品准入、询报价 | 见【待确认-35】。成品价格在ERP的价格管理 |
| 供货范围 | 即使以后记录，也不能限制SRM下单。见[待对齐事项A09](11.待对齐事项.md)、【待确认-40】 |
| 驻厂验货记录 | 阶段4写了驻厂QC按节点抽检，但记录放在门户还是品质系统，见【待确认-20】 |
| 质量异常 | 不合格要能追溯。一期是否单独立单，还是先附在收货结果上，没有定论。检验系统见【待确认-09】 |

## 三、和ERP单据怎么配对

| 门户对象 | ERP单据 | 配对规则 |
| --- | --- | --- |
| SRM采购订单 | ERP采购订单 | 一张对一张，不合并、不拆分。ERP副本只读。两边单号是否相同，见【待确认-05】 |
| 交期建议 | ERP采购订单上的承诺交期 | 多条建议可以并存。只有已经从SRM推送成功的那次，才是两边当前的承诺交期 |
| 发货单 | 采购收货通知单，前缀CGSHTZ | 目标是一张发货单生成一张通知单，并回填通知单号。是否允许例外，见【待确认-07】 |
| 发货单行 | SRM采购订单行，以及ERP上的对应行 | 一行订单可以分多次发货。未确认前按「一单、一仓」理解，以免和ERP通知单的单头来源冲突 |
| 收货结果视图 | 采购收货通知单和采购入库单，前缀CGRK | ERP一次通知只有一个最终结果。实收为0时通知取消，没有入库单。SRM不出现零数量入库 |
| 退货协同视图 | 采购退货单、采退发货通知单、采退出库单 | 只跟踪，不在门户另做退货入库 |
| 对账单行 | 采购入库单、采退出库单 | 不取发货数量。订单和通知单本身不对账 |
| 开票申请、税票 | 无对应ERP单据 | 通过入库单、采退出库单向上追到通知单、发货单、SRM采购订单和ERP采购订单 |

采购退货的前缀以ERP对照表为准：采购退货单CGTH，采退发货通知单CTFHTZ，采退出库单CTCK。见[ERP编码规则](https://github.com/TopVitamin/QS-ERP-Project/blob/main/01-全局背景信息/6.强盛ERP的编码规则和通用字段规则.md)。这些前缀不是SRM自己的单号前缀。

## 四、追溯链要能串起来

阶段5要求抽到一笔入库时，能往前看到采购单，往后看到发票和凭证。目标链条是：

```plain
税票 / 红字确认记录
    → 开票申请
    → 对账单
    → 采购入库单或采退出库单
    → 采购收货通知单
    → 发货单和箱码
    → SRM 采购订单
    → ERP 采购订单
    → 金蝶凭证和银行流水
```

业务往前走的时候，顺序是SRM采购订单推到ERP，ERP再形成收货通知和入库，入库进入金蝶。往回查的时候，从税票能点回SRM订单，也能点到ERP上的那张只读订单。

准入核验和同SKU的价格对比，是上市问询里常见的证据。强盛有没有这些记录、放不放在门户，见【待确认-32】【待确认-35】。没有记录时，不能在链条上画一个空节点假装已经留痕。

银行流水和凭证在金蝶，门户不复制一份资金账。

## 五、本文故意不写的内容

- 每张单据的状态名称、允许的跳转和并发。
- 表头表体字段、必填和默认值。
- 接口字段名、重试次数和错误码。重试原则见[全局规则](4.强盛SRM全局业务规则与约束.md)，参数见【待确认-06】。
- 页面上按钮的位置。

后续目录如果给发货单设计状态，必须同时满足本文的分层：发货单的任何状态都不能表示「仓库已经按门户指令收货」。收货是否完成，只看ERP通知单和入库单。
