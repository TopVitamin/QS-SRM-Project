## 一、协同门户指什么

协同门户是强盛自研的供应商协同系统，也是采购员创建采购订单的主工作台。采购订单在这里创建并审核。审核通过后推送ERP。ERP只读持有这张订单，负责库存、在途、成本和业财，并把收货通知下发给WMS。

| 职责 | 说明 |
| --- | --- |
| 采购订单 | 采购员创建并审核成品采购订单。审核通过后推送ERP。变更只能在SRM发起 |
| 订单协同 | 收集供应商的确认、拒绝和交期建议。和推送的先后见【待确认-02】 |
| 交付过程 | 留下齐套和进度节点，生成发货单、箱码和预约 |
| 结果展示 | 只读展示经ERP回传的实收、拒收和退货。不从WMS另接一条库存 |
| 对账与税票 | 以ERP已审核结果单为基准做双方确认，登记数电票和红字确认过程。核算在金蝶 |
| 隔离与留痕 | 供应商只能看本公司数据。关键动作记录操作者、时间和前后值 |

**不由门户承担的工作：**

- 库存、在途、存货成本和业财编排。这些在ERP。
- 给仓库下达收货、上架、拣货、盘点指令。箱码和预约是收货的预期，不是库存账。
- 应付、付款、预付、核销、凭证、总账。预付款继续在线下处理。
- 代工厂的BOM、车间和MES。
- 领星、聚水潭的订单和履约，以及门店POS。
- 采购申请或采购计划的计算。来源见【待确认-01】。

## 二、各系统分工

```plain
采购员在 SRM 创建并审核采购订单
        │ 审核通过后推送（一张对一张）
        ▼
自研 ERP ──只读持有采购订单，负责库存、在途、成本、业财
   │
   ├── 采购收货通知单 ──► WMS 执行
   │                         │
   │                         └── 实际结果回 ERP
   │                                │
   │                                └── 采购入库单回传 SRM（只读）
   │
   └── 已审核采购入库单、采退出库单 ──► 金蝶云·星空

供应商在 SRM 确认、反馈、提交发货单、箱码和预约。
主数据平台（阶段5）分发 SKU、客户、组织。供应商是否上移，尚未确定。
领星、聚水潭、门店不连接门户。
```

| 系统 | 承担的工作 | 和门户的交界 |
| --- | --- | --- |
| 自研SRM | 采购订单的创建、审核和变更发起；供应商确认、发货预告、箱码、预约、对账和税票协同 | 本系统。推送失败不另建第二张订单 |
| 自研ERP | 只读接收采购订单；库存、在途、成本、业财；采购收货通知单、采购入库单、采购退货链 | 不在ERP里新建或修改采购订单。收货通知由ERP生成并下发WMS |
| 仓库作业系统 | 收货、上架、质检执行、批次和库位 | 只执行ERP的采购收货通知单。门户不直接下指令。箱码要能被现场扫描查回，码制见【待确认-23】 |
| 金蝶云·星空 | 存货核算、应付、发票核销、总账 | 不创建业务采购订单。税票和应付的衔接见下文，路径见【待确认-14】 |
| 主数据平台 | 阶段5叙事里SKU、客户、组织的唯一源头，单向分发 | 清单中没有供应商。门户不成为供应商主数据的源头。归属见【待确认-13】 |
| 领星 / 聚水潭 | 跨境和国内电商的运营、履约 | 不对接门户。渠道销量影响采购量的过程不经过门户改库存 |
| 中央OMS | 阶段5叙事中的订单路由 | ERP一期明确不建中央OMS。门户不把它写成已交付的上游。计划来源见【待确认-01】 |
| 代工厂自有系统 | 车间生产和工序 | 人在门户里填节点。系统之间不对MES做接口 |
| 门店POS / 小程序 | 直营、加盟门店的零售和自提 | 不向供应商下单，不对接门户 |

阶段4背景把深圳主仓写成自研WMS，阶段5把五个国内区域仓也写成自研WMS。ERP立项时点写的是深圳主仓当时没有专业WMS，一期引入第三方WMS。WMS仓库的立项范围是四个海外仓。这些是不同时点的口径，预约要对接哪一套，见【待确认-21】和[待对齐事项A15](11.待对齐事项.md)。

## 三、业务链路

### 3.1 采购订单

采购员在SRM创建并审核采购订单。审核通过后推送ERP。ERP持有的是只读副本，不是第二张采购合同。一张SRM订单对应一张ERP订单，推送时不合并、不拆分。

```plain
采购员在 SRM 创建并审核
    → 审核通过后推送 ERP
    → 失败则保留 SRM 订单，记下失败，重试同一笔推送
    → 成功后 ERP 只读持有
    → 供应商确认 / 拒绝（须写原因） / 提交交期建议
    → 交期建议由采购在 SRM 接受或驳回
    → 需要变更时，只能从 SRM 发起，再推送 ERP
```

采购申请或采购计划从哪里来，见【待确认-01】。供应商确认与推送的先后、拒绝的订单是否推送，见【待确认-02】。已经推送之后允许改哪些字段，见【待确认-03】。两边单号是否相同、用什么做幂等键，见【待确认-05】。重试次数、间隔和核对频率，见【待确认-06】。不把ERP仓库推送「最多3次」写成这里的参数。

同一张SRM订单不得因为超时或失败而在ERP再建一张。核对时比对单号、供应商、行、数量、价格、交期和关闭状态。

关闭和取消由谁发起，见【待确认-04】。已关闭的订单不能再新建发货。关闭后已经在途的收货通知是否继续，ERP旧文写「继续执行」，是否仍适用也见【待确认-04】。SRM不自己做反关单。

24小时是阶段4写明的确认时限。超时之后算不算自动接受、未确认能否发货、能否带条件接受，见【待确认-19】。

### 3.2 齐套和进度

齐套不是物料需求计算。它是挂在SRM采购订单行上的关键物料节点：供应商标明已经齐套，或者登记缺料。缺料时写下物料名称、预计到料日和对交期的影响。具体节点清单见【待确认-20】。

驻厂人员可以复核节点。复核记录放在门户还是品质系统，没有定。来料检验如果发生在仓库，结果以仓库回传给ERP的记录为准，门户只读，见【待确认-09】。

距承诺交期前10天，节点未完成就预警。阶段5的默认值收紧为7天。预警是提醒，不自动改订单，也不自动关闭。

### 3.3 发货、箱码和收货指令

三层仍然分开：SRM采购订单是业务安排，ERP采购收货通知单是执行指令，ERP采购入库单是实际结果。门户的发货单是「供应商对这一批货的预告」，不是第二张收货指令。

```plain
供应商提交发货单（数量、批次、箱码、物流）
    → ERP 按发货单生成采购收货通知单，并把通知单号回填发货单
    → ERP 把通知单下发给 WMS
    → WMS 执行一次收货，结果回 ERP
    → 允许缺量，拒绝超量
    → 零收时 ERP 取消该通知，不生成入库单
    → 采购入库单回传 SRM，门户不另记一套库存
```

ERP现文仍写采购在ERP里代录通知单，或从ERP订单下推。那是旧口径，见[待对齐事项A03](11.待对齐事项.md)，ERP文档后续另行对齐。接口还不能由发货单生成通知单时，不能改成门户直接指挥WMS，也不能把代录写回现行规则。代录只留给尚未上线的供应商，并记下代录人、时间和依据。

一张发货单先按一张采购订单、一个收货仓来理解，以便贴住ERP通知单「单头一个来源订单」的结构。能否一车多单、是否严格一张发货单生成一张通知，见【待确认-07】。不进仓的虚拟入库要不要走发货单，见【待确认-08】。

箱是作业容器。库存按SKU和批次记在ERP、WMS，门户不建箱库存。作废的箱码不能再当有效箱收货。补打和码制见[编码规则](6.强盛SRM的编码规则和通用字段规则.md)。

预约记录目标仓、日期时段、车牌和件数。仓点清单见【待确认-21】。是否必须人工确认、爽约怎么算，见【待确认-24】。

### 3.4 收货结果和采购退货

供应商只读查看经ERP回传的实收、拒收、质检和退货。回传内容见【待确认-09】。现场拒收在ERP里按缺量回传，不单独做一种库存交易。

采购退货沿用ERP的采购退货单、采退发货通知单、采退出库单。门户做确认和跟踪，不决定补货还是扣款。补货是否占用原订单额度，见【待确认-10】。需要新的采购订单时，在SRM创建并推送，不在ERP再建，见[待对齐事项A08](11.待对齐事项.md)。

实到多于通知数量时，ERP直接拒绝这次回传。多出来的货如何处理，见【待确认-10】。

### 3.5 对账、开票和金蝶

```plain
ERP 已审核的采购入库单、采退出库单
    → SRM 按供应商和期间形成对账基准
    → 供应商确认，或只提出差异（不能改数量和单价）
    → 已确认之后才能做开票申请
    → 供应商登记数电票；红字按税务规则协同
    → 金蝶做应付、发票核销和凭证
```

金蝶公开手册的采购入库核算是：入库单下推应付单确定入库成本，收到发票后应付单与发票核销，有差异再走应付调整。见[金蝶云·星空采购入库核算](https://help.open.kingdee.com/dokuwiki_std/doku.php?id=%E9%87%87%E8%B4%AD%E5%85%A5%E5%BA%93%E6%A0%B8%E7%AE%97%E5%BA%94%E7%94%A8)。门户里的勾稽是双方确认和预校验，不是这套账务处理。

谁发起对账，见【待确认-16】。税票和开票申请的组合规则见【待确认-18】。红字确认单的操作主体见【待确认-14】。开票主体有几个，见【待确认-15】。

上市审计要能从SRM采购订单点到ERP采购订单、采购入库单，再点到金蝶的凭证和流水。银行流水和凭证不在SRM复制一份。

### 3.6 主数据

```plain
供应商、成品 SKU（ERP 维护，阶段5是否上移见【待确认-13】）
    → SRM 只读引用，编码不另编
    → 供应商用户、联系人、送货地址可以在门户维护协同信息
    → 账期、结算方式和采购价格仍以 ERP / 财务为准
```

门户不向领星、聚水潭推SKU。商品与供应商的供货关系，ERP一期不建。门户不能用一份供货范围去拒绝SRM下单，见[待对齐事项A09](11.待对齐事项.md)。

## 四、数据往哪边流

| 方向 | 传什么 | 说明 |
| --- | --- | --- |
| SRM → ERP | 已审核采购订单、此后由SRM发起的变更、发货单 | 一张对一张。失败保留原单并重试同一笔。不回写由ERP自行改数量或价格 |
| ERP → SRM | 推送结果、只读的订单副本状态、采购入库单和采退出库单 | 入库以ERP采购入库单为准。不从WMS直连SRM记库存 |
| ERP → WMS | 采购收货通知单、采退发货通知单 | 唯一的收货和退货执行指令 |
| WMS → ERP | 实际收货、出库、质检结果 | 记账在ERP |
| SRM → WMS | 预期中的箱码和预约 | 只帮助识别和排窗口，不驱动收货过账。外部仓是否认这套箱码，见【待确认-22】 |
| SRM → 金蝶 | 尚未定 | 不能先写成「发票号回写ERP」。见【待确认-14】和[待对齐事项A06](11.待对齐事项.md) |
| ERP → 金蝶 | 已审核的采购入库单、采退出库单 | 沿用ERP七类结果单的范围。订单、通知、发货单、对账单不在这七类里 |

推送失败不另建一张业务单去补账。ERP侧已有的原则是：结果单推送失败不回滚已经生效的库存。SRM到ERP的订单推送另有一条：失败时SRM订单还在，ERP还没有这张订单，重试的是同一笔，参数见【待确认-06】。

## 五、三条必须先记住的边界

1. **采购订单在SRM创建，ERP只读。** 变更只能在SRM发起。允许改哪些字段见【待确认-03】。
2. **发货单不是收货指令。** 仓库只认ERP采购收货通知单，由ERP下发给WMS。
3. **税票不是应付，入库结果不从WMS直连接SRM。** 应付和核销在金蝶。SRM只读ERP已经审核的采购入库单。

字段、状态机、页面和接口放在后续的需求与产品设计里。本文的链路表示目标边界，不表示接口已经联调。标了【待确认】的，不能当成验收条件。
