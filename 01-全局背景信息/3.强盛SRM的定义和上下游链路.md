## 一、协同门户指什么

协同门户是强盛自研的供应商侧系统。它不拥有采购订单、收货通知和入库结果，只承接供应商能看见、能回复、能留下证据的那一层。

| 职责 | 说明 |
| --- | --- |
| 订单协同 | 展示ERP已审核的成品采购订单，收集确认、拒绝和交期建议 |
| 交付过程 | 留下齐套和进度节点，生成发货单、箱码和预约 |
| 结果展示 | 只读展示ERP、WMS已经确认的实收、拒收和退货 |
| 对账与税票 | 以ERP已审核结果单为基准做双方确认，登记数电票和红字确认过程。核算在金蝶 |
| 隔离与留痕 | 供应商只能看本公司数据。关键动作记录操作者、时间和前后值 |

**不由门户承担的工作：**

- 采购数量的计算、采购订单的审核、数量和价格的修改。
- 给仓库下达收货、上架、拣货、盘点指令。箱码和预约是收货的预期，不是库存账。
- 应付、付款、预付、核销、凭证、总账。预付款继续在线下处理。
- 代工厂的BOM、车间和MES。
- 领星、聚水潭的订单和履约，以及门店POS。

## 二、各系统分工

```plain
供应商在门户确认、反馈、发货、预约
        │ 交期建议、发货单
        ▼
自研 ERP ──已审核采购订单、供应商、SKU──► 门户
   │  ▲
   │  └── 实收、质检结果（门户只读同步）
   │
   ├── 采购收货通知单 ──► 仓库执行（自营仓或外部仓的作业系统）
   │                         │
   │                         └── 实际结果回 ERP
   │
   └── 已审核采购入库单、采退出库单 ──► 金蝶云·星空

主数据平台（阶段5）分发 SKU、客户、组织。供应商是否上移，尚未确定。
领星、聚水潭、门店不连接门户。
```

| 系统 | 承担的工作 | 和门户的交界 |
| --- | --- | --- |
| 自研ERP | 供应商和成品SKU的业务主数据、采购订单、采购收货通知单、采购入库单、采购退货链、逻辑库存 | 下发已审核订单和关闭结果。接收的只是协同记录。库存和财务推送仍由ERP自己做 |
| 仓库作业系统 | 收货、上架、质检执行、批次和库位 | 只执行ERP的采购收货通知单。门户不直接下指令。箱码要能被现场扫描查回，码制见【待确认-15】【待确认-16】 |
| 金蝶云·星空 | 存货核算、应付、发票核销、总账 | 不与门户做采购订单。税票和应付的衔接见下文，路径见【待确认-08】 |
| 主数据平台 | 阶段5叙事里SKU、客户、组织的唯一源头，单向分发 | 清单中没有供应商。门户不成为供应商主数据的源头。归属见【待确认-07】 |
| 领星 / 聚水潭 | 跨境和国内电商的运营、履约 | 不对接门户。渠道销量影响采购量的过程在ERP，不经过门户 |
| 中央OMS | 阶段5叙事中的订单路由 | ERP一期明确不建中央OMS。门户不把它写成已交付的上游，见[待对齐事项A09](11.待对齐事项.md) |
| 代工厂自有系统 | 车间生产和工序 | 人在门户里填节点。系统之间不对MES做接口 |
| 门店POS / 小程序 | 直营、加盟门店的零售和自提 | 不向供应商下单，不对接门户 |

阶段4背景把深圳主仓写成自研WMS，阶段5把五个国内区域仓也写成自研WMS。ERP立项时点写的是深圳主仓当时没有专业WMS，一期引入第三方WMS。WMS仓库的立项范围是四个海外仓。这些是不同时点的口径，预约要对接哪一套，见【待确认-13】和[待对齐事项A14](11.待对齐事项.md)。

## 三、业务链路

### 3.1 采购订单

ERP审核采购订单后下发门户。供应商看到的是投影，不是第二张订单。

```plain
ERP 采购订单（已审核） → 门户待确认
    → 供应商确认 / 拒绝（须写原因） / 提交交期建议
    → 交期建议由采购接受或驳回
    → 接受之后，只有 ERP 调整了承诺交期，到期关闭日才跟着变
```

数量和价格在门户里是只读的。关闭、取消以ERP为准：已关闭的订单不能再新建发货；已经在途的发货是否继续收，按ERP「关闭后已有通知继续执行」处理，门户只展示，不自己判断能否反关单。

24小时是阶段4写明的确认时限。超时之后算不算自动接受、未确认能否发货，见【待确认-18】。带条件接受见【待确认-19】。

### 3.2 齐套和进度

齐套不是物料需求计算。它是挂在采购订单行上的关键物料节点：供应商标明已经齐套，或者登记缺料。缺料时写下物料名称、预计到料日和对交期的影响。具体节点清单见【待确认-24】。

驻厂人员可以复核节点。复核记录放在门户还是品质系统，没有定。来料检验如果发生在仓库，结果以仓库系统为准，门户只读，见【待确认-25】。

距承诺交期前10天，节点未完成就预警。阶段5的默认值收紧为7天。预警是提醒，不自动改订单，也不自动关闭。

### 3.3 发货、箱码和收货指令

ERP的三层是：采购订单是业务安排，采购收货通知单是执行指令，采购入库单是实际结果。门户的发货单对应的是「供应商对这一批货的预告」，不是第二张收货指令。

```plain
供应商提交发货单（数量、批次、箱码、物流）
    → 目标：接口在 ERP 生成采购收货通知单，并把通知单号回填发货单
    → ERP 按已有规则推送仓库、接收一次实际结果、允许缺量、拒绝超量
    → 零收时 ERP 取消该通知，不生成入库单
    → 门户展示结果，不另记一套库存
```

在ERP提供来源类型之前，通知单仍由采购按供应商反馈代录。代录要记下代录人、时间和依据。见[待对齐事项A02](11.待对齐事项.md)。

一张发货单对应一张采购订单、一个收货仓，是为了贴住ERP通知单「单头一个来源订单」的结构。能否一车多单，见【待确认-20】。不进仓的虚拟入库要不要走发货单，见【待确认-12】。

箱是作业容器。库存按SKU和批次记在ERP、WMS，门户不建箱库存。作废的箱码不能再当有效箱收货。补打和码制见[编码规则](6.强盛SRM的编码规则和通用字段规则.md)。

预约记录目标仓、日期时段、车牌和件数。仓点清单见【待确认-13】。是否必须人工确认、爽约怎么算，见【待确认-17】。

### 3.4 收货结果和采购退货

供应商只读查看实收、拒收、质检和退货。现场拒收在ERP里按缺量回传，不单独做一种库存交易。拒收原因回不回门户，见【待确认-25】。

采购退货沿用ERP的采购退货单、采退发货通知单、采退出库单。门户做确认和跟踪，不决定补货还是扣款。补货是否占用原订单额度，见【待确认-26】。

实到多于通知数量时，ERP直接拒绝这次回传。多出来的货退回还是另建通知，见【待确认-26】。

### 3.5 对账、开票和金蝶

```plain
ERP 已审核的采购入库单、采退出库单
    → 门户按供应商和期间形成对账基准
    → 供应商确认，或只提出差异（不能改数量和单价）
    → 已确认之后才能做开票申请
    → 供应商登记数电票；红字按税务规则协同
    → 金蝶做应付、发票核销和凭证
```

金蝶公开手册的采购入库核算是：入库单下推应付单确定入库成本，收到发票后应付单与发票核销，有差异再走应付调整。见[金蝶云·星空采购入库核算](https://help.open.kingdee.com/dokuwiki_std/doku.php?id=%E9%87%87%E8%B4%AD%E5%85%A5%E5%BA%93%E6%A0%B8%E7%AE%97%E5%BA%94%E7%94%A8)。门户里的勾稽是双方确认和预校验，不是这套账务处理。

谁发起对账，见【待确认-22】。税票和开票申请的组合规则见【待确认-21】。红字确认单的操作主体见【待确认-08】。开票主体有几个，见【待确认-09】。

### 3.6 主数据

```plain
供应商、成品 SKU（ERP 维护，阶段5是否上移见【待确认-07】）
    → 门户只读引用，编码不另编
    → 供应商用户、联系人、送货地址可以在门户维护协同信息
    → 账期、结算方式和采购价格仍以 ERP / 财务为准
```

门户不向领星、聚水潭推SKU。商品与供应商的供货关系，ERP一期不建。门户不能用一份供货范围去拒绝ERP下单，见[待对齐事项A07](11.待对齐事项.md)。

## 四、数据往哪边流

| 方向 | 传什么 | 说明 |
| --- | --- | --- |
| ERP → 门户 | 供应商、成品SKU、已审核采购订单、关闭和取消 | 订单数量、价格、承诺交期以ERP为源。门户不回写数量和价格 |
| 门户 → ERP | 接单结果、交期建议、发货单 | 交期只有ERP接受调整后才改变订单。发货单生成通知单仍待ERP接口 |
| ERP → 仓库 | 采购收货通知单、采退发货通知单 | 唯一的收货和退货执行指令 |
| 仓库 → ERP | 实际收货、出库、质检结果 | 记账在ERP。门户从ERP取只读结果，不与仓库各记一笔 |
| 门户 → 仓库 | 预期中的箱码和预约 | 只帮助识别和排窗口，不驱动收货过账。外部仓是否认这套箱码，见【待确认-14】 |
| 门户 → 金蝶 | 尚未定 | 不能先写成「发票号回写ERP」。见【待确认-08】和[待对齐事项A03](11.待对齐事项.md) |
| ERP → 金蝶 | 已审核的采购入库单、采退出库单 | 沿用ERP七类结果单的范围。订单、通知、发货单、对账单不在这七类里 |

推送失败不在门户里另建一张业务单去「补账」。ERP侧已有的原则是：推送失败不回滚已经生效的结果和库存。门户不发明第二套重推办法。

## 五、三条必须先记住的边界

1. **交期建议不是变更单。** 数量和价格不能从门户改。承诺交期以ERP调整后的值为准。
2. **发货单不是收货指令。** 仓库只认ERP采购收货通知单。门户直推WMS收货，和ERP定稿冲突。
3. **税票不是ERP单据。** 应付和核销在金蝶。门户做确认、预校验和追溯键。

字段、状态机、页面和接口放在后续的需求与产品设计里。本文的链路表示目标边界，不表示接口已经联调。标了【待确认】的，不能当成验收条件。
