## 一、为什么做

### 1.1 触发点

强盛把生产全部放在代工厂，自己做品牌和渠道。阶段4参股了3家核心代工厂之后，工厂进度仍然靠微信。新品可以在交货前一周才暴露缺料，客诉也追不回电芯批次。

公司需要的不是再买一套把寻源、商城、车间都包进来的SRM，而是一个自己能掌控的供应商门户：ERP已经审核的成品采购订单，要能在线接单、反馈交期和齐套、打印外箱码、预约到仓；阶段5还要能把对账和发票留在同一条单据链上。实物收货仍在仓库，法定核算仍在金蝶。

ERP一期已经写明不做自研SRM、供应商在线协同和商品供货关系。所以门户是独立项目，不塞进ERP采购模块。

### 1.2 要对齐的缺口

| 缺口 | 背景里的表现 | 门户要对准什么 |
| --- | --- | --- |
| 交付黑盒 | 订单下发后，接单、齐套、产线进度看不见 | 24小时内确认交期；按节点留下齐套和进度；到期前预警 |
| 外箱对不上仓 | 没有标准外箱码时，仓库不能按箱盲扫，批次链断开 | 发货前打印能被仓库识别的外箱码，至少能查回采购订单、SKU、批次和数量 |
| 到仓无窗口 | 货车直接到月台，和质检、大促收货抢资源 | 预约送货，由仓侧确认窗口。直播快发走专属月台，这是阶段5的增强 |
| 参股厂仍靠催 | 3家参股厂用自己的系统生产 | 只协同成品交付和关键齐套节点，不接管工厂的MES和BOM |
| 审计在发票处断开 | 尽调要求采购单、入库、发票、银行流水、凭证能互相点开 | 对账和开票协同留痕。应付、付款、凭证在金蝶，不在本系统核算 |
| 工厂接入慢 | 上线初期未全量接入，历史订单未迁移 | 门户要轻，采购可以代录。历史订单怎么迁，见【待确认-32】 |

预警的天数有两个时点：阶段4是距交期前10天，阶段5收紧为7天。两档都写进规则，不把7天回写成2020年的事实。

### 1.3 为什么自研，而不是把门户开在别的系统上

| 方案 | 能对照的能力 | 本项目的取舍 |
| --- | --- | --- |
| 甄云、商越、用友采购云等整包SRM | 订单确认、送货条码、对账和发票协同 | 单据流可以借鉴。整包还带寻源、商城和制造协同，会和已经自研的ERP、WMS抢入口 |
| 金蝶云·星空供应商协同、星瀚SRM | 送货通知、条码、对账、开票工作台，和金蝶财务一体 | 财务继续用金蝶。业务采购订单在自研ERP。门户若开在金蝶，供应商会把业务入口带回财务系统 |
| SAP Business Network、Coupa、Oracle Supplier Portal | ASN、分包进度、发票协同的概念 | 只作能力对照。200多家国内中小代工厂的接入方式和语言，不适合拿它们当主门户 |
| 震坤行等MRO商城 | 间接物料的目录采购 | 与成品代工交付不是一条链，后期如要做，另立范围 |

因此：采购订单的所有权在ERP，供应商侧的协同入口在本系统，仓内作业在WMS，法定账在金蝶。

## 二、这个项目是什么

| 项 | 说明 |
| --- | --- |
| 项目名称 | 强盛科技自研SRM（供应商协同门户） |
| 建设方式 | 独立自研。不替换领星、聚水潭、金蝶，也不并进ERP一期 |
| 核心定位 | 面向供应商的协同层：把ERP已审核的成品采购订单，变成可确认、可反馈、可预警、可贴码、可预约的在线过程；阶段5再把对账和开票信息接到同一条追溯链 |
| 不承担的职责 | 不算采购量，不改订单数量和价格，不给仓库下收货指令，不建应付，不排产 |
| 优先接入 | 3家参股代工厂先接入，再铺开200多家。接入顺序是建议，不是已签署计划 |

```plain
ERP 审核采购订单 → 下发门户
    → 供应商确认、反馈交期和齐套、提交发货与箱码、预约到仓
    → 仓库按 ERP 的采购收货通知单收货（通知单如何生成，见上下游链路）
    → 实收结果回到 ERP，门户只读展示
    → 对账和税票信息供金蝶核销，门户不做付款
```

## 三、建设范围

范围分成两段，对应背景里的两个时点。两段都还不是已确认的项目排期。字段、状态枚举和接口报文不在本篇展开。

### 3.1 第一段：交付协同

这一段对应2020年上半年叙事里的门户，也是本仓库所说的一期。

| 模块 | 要做什么 | 不在这一段里做完的 |
| --- | --- | --- |
| 门户与账号 | 企业侧开通供应商用户；供应商用浏览器办理；采购可代录 | 供应商能否自己建子账号，见【待确认-30】 |
| 主数据 | 只读使用ERP的供应商和成品SKU | 不另编供应商编码，不建供货关系去限制ERP下单 |
| 订单协同 | 接收已审核采购订单；24小时内确认、拒绝或提交交期建议；订单关闭后禁止再发货 | 不改数量和价格，不建变更单 |
| 交期与齐套 | 按节点反馈关键物料是否齐备；距交期前10天预警 | 节点名称和哪些必报，见【待确认-24】。不是MRP |
| 发货与箱码 | 一次发货的数量、批次、箱码；预约仓、日期和车辆 | 箱码码制见【待确认-15】【待确认-16】。收货指令仍是ERP的采购收货通知单 |
| 收货结果 | 只读展示实收、拒收和质检结果 | 检验单据落在哪个系统，见【待确认-25】 |
| 留痕 | 供应商的确认、发货、代录要记下操作者和时间 | 与ERP「完整操作日志不是一期必做」的差异，见[待对齐事项A08](11.待对齐事项.md) |

### 3.2 第二段：阶段5增强

| 模块 | 要做什么 | 还没定的 |
| --- | --- | --- |
| 预警 | 默认提前7天，可按协同成熟度配置 | 参股厂是否单独更短，阈值未给出 |
| 直播交付 | 半成品备料完成量可见；外箱码支持月台快收 | 备料单据见【待确认-10】 |
| 对账 | 以ERP已审核的采购入库单、采退出库单为基准，双方确认 | 谁发起、多久一次，见【待确认-22】 |
| 开票 | 开票申请、数电票登记和预校验、红字确认单的协同记录 | 推送金蝶的路径见【待确认-08】。查验是否必须在门户内完成，见【待确认-33】 |
| 参股厂 | 同一套单据，另给齐套模板和看板 | 不因此看到其他供应商的价格 |

寻源、招投标、采购商城、VMI、车间报工不放进这两段。费用单、委外供料、样品准入只有同行和软件手册的做法，强盛自己没有给出事实，分别见【待确认-27】【待确认-11】【待确认-31】。

## 四、不做什么

| 类别 | 不做什么 | 依据 |
| --- | --- | --- |
| 生产 | BOM、MRP、车间排产、工序报工、与代工厂MES直连 | 背景写明生产在代工厂自己的系统里 |
| 计划与库存 | 采购需求计划、自动补货、逻辑库存、渠道配额、中央OMS | ERP一期明确不做计划模型和中央OMS。门户不把它们当成自己的上游 |
| 仓内作业 | 库位、上架、拣货、盘点、FIFO执行 | 在WMS。门户给出的是箱码和预约，不是收货记账 |
| 财务 | 应付、付款、预付、核销、凭证、总账、存货成本 | 在金蝶。预付继续线下处理，与ERP定稿一致 |
| 前台 | 领星、聚水潭的抓单和打单；门店POS | 渠道继续分治。门店不向供应商下单 |
| 重型采购 | 全量招投标、竞价大厅、员工福利商城、MRO目录 | 成品交付才是主矛盾。间接物料如要做，另立项目 |
| 越权改单 | 改已审核订单的数量和价格；直接关闭或重开ERP订单；向WMS另下一张收货指令 | 与ERP定稿冲突的写法已收进待对齐事项 |

销售退货、仓间调拨、消费者退款都不在本系统。采购退货只展示ERP已经生成的退货链，供供应商确认和跟踪。

## 五、建议的落地顺序

下面是阅读和设计时的先后，不是排期。调研报告里的甘特月份是教学示意，不能当成开工日期。

1. 供应商开通、只读主数据、操作留痕。没有账号和隔离，后面的单据不能给工厂用。
2. 采购订单确认、交期建议、关闭同步。先保证工厂看到的订单和ERP是同一张。
3. 齐套节点和10天预警。先解决「交货前一周才说缺料」。
4. 发货单、箱码、预约，并与ERP采购收货通知单对齐。仓库只认一张指令。
5. 收货结果只读。实收以ERP、WMS为准。
6. 阶段5再做7天预警、半成品备料可见、对账、开票申请和红字确认单协同。

第4步依赖ERP是否提供「由发货单生成采购收货通知单」的接口。接口未定时，不能把「门户直推WMS」写成替代方案。见[待对齐事项A02](11.待对齐事项.md)。

## 六、部门在本项目里要什么

| 部门 | 诉求 | 在门户里的动作 |
| --- | --- | --- |
| 计划部 | 承诺交期和备料看得见 | 只读。不在门户里改采购数量 |
| 采购 | 少靠微信催，风险提前出现 | 跟单、处理交期建议、为未上线的供应商代录 |
| 仓储物流（阿盛） | 货车按窗口来，箱子能扫 | 确认预约。扫码收货在WMS，不在门户 |
| 品质中心 | 批次能追，驻厂抽检有记录 | 复核齐套；验货记录放在门户还是品质系统，见【待确认-24】【待确认-25】 |
| 财务（阿兰） | 对账数和发票能点回采购单 | 定对账和容差。容差见【待确认-23】。付款仍在金蝶 |
| 数字化中心 | 边界清楚 | 主数据和接口只走ERP、WMS、金蝶，不再加一套催货表 |
| 营销中心 | 新品和直播不断供 | 不直接操作系统 |
| 代工厂 | 指令清楚，少填第二遍 | 接单、反馈、贴码、预约、对账 |

人物只帮助理解参与方，不映射账号和审批流。
