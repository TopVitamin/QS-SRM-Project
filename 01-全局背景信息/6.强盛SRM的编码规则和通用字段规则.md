# 强盛SRM的编码规则和通用字段规则

> 更新日期：2026-10-15。
>
> 本文只写编号、主数据引用和箱码的标识规则。字段级模板、枚举和校验放在后续产品设计。数据库类型和接口错误码不在这里规定。
>
> 供应商、SKU、ERP结果单据号已经有定稿的，门户直接引用，不另编一套。见[ERP编码规则](https://github.com/TopVitamin/QS-ERP-Project/blob/main/01-全局背景信息/6.强盛ERP的编码规则和通用字段规则.md)。下文标成建议的前缀，正式值都还是【待确认】，不能拿去印标签。

---

## 一、单号

### 1.1 采购订单号和幂等

SRM采购订单和ERP采购订单是一张对一张。推送时不合并、不拆分。同一张SRM订单不得在ERP变成第二张。

ERP是否沿用SRM的采购订单号，还是另编`CGDD`并把SRM单号保存为来源，没有选定，见【待确认-05】。在此之前：

- 不把`CGDD`印成SRM自己的前缀。
- 也不把下面的建议前缀印到采购订单上。
- 幂等先按「同一张SRM订单只对应一张ERP订单」执行。用哪个字段当幂等键，同样见【待确认-05】。

### 1.2 门户其他单据的格式

ERP单据号是`{前缀}-{YYYYMMDD}-{序号}`，例如`CGDD-20260818-0001`。日期是创建日，序号同类型同一天从0001起，超过9999位扩成5位，作废后不重用。单号里不拼来源单号。

门户面向国内工厂，建议使用同一格式，不采用WMS仓库的两位英文字母。原因是WMS的英文简码服务于海外仓现场；门户的使用者是中文采购和代工厂。这是建议，不是已经和WMS共同签过的码制。

建议的生成方式：

- 前缀用单据中文名的拼音首字母，2至6位大写字母，同一类型固定。
- 保存时生成，用户不能改，删除或作废后不重用。
- 和ERP的关联放在来源单号字段里。收货通知单号、入库单号不拼进门户单号。

### 1.3 建议前缀

正式前缀没有确认。下表只避免和ERP已占用的前缀撞车，方便讨论。印在单据上之前必须先改掉「建议」两字。采购订单不在此表，见1.1。

| 对象 | 建议前缀 | 示例 | 说明 |
| --- | --- | --- | --- |
| 发货单 | FHD | FHD-20260818-0001 | 不叫ASN单号。ASN只是口头简称，见[术语表](10.术语表.md) |
| 预约送货 | YYSH | YYSH-20260818-0001 | |
| 交期建议 | JYJS | JYJS-20260818-0001 | 也可以只做订单下的行记录、不单独编号。是否独立成单，后续再定 |
| 对账单 | DZD | DZD-20260818-0001 | 阶段5 |
| 开票申请 | KPSQ | KPSQ-20260818-0001 | 阶段5。不是税票号码 |

箱码不走这套日期流水，见第三节。接单确认、预警、操作日志如果不能单独被引用，可以不发业务单号。

ERP已经占用、门户不能再拿来当自己前缀的，包括CGDD、CGSHTZ、CGRK、CGTH、CTFHTZ、CTCK。完整清单以ERP对照表为准。

## 二、主数据编号不另编

| 对象 | 规则 |
| --- | --- |
| 供应商 | 沿用ERP的`SUP`加6位序号，例如`SUP000001`。门户不发第二套供应商编码 |
| 成品SKU | 沿用ERP商品编码。门户不建SPU，不编原材料编码 |
| 仓库 | 预约和发货要引用ERP的实体仓编码（`WH`加6位序号）。可选哪些仓，见【待确认-21】 |
| 展示 | 引用时用Code-Name：编码和名称之间一个空格，例如`SUP000001 深圳示例电子有限公司`。接口仍传编码或内部标识，不把名称拼进主键 |

供应商用户的登录名怎么编，背景没有规定，见【待确认-34】。不要把供应商编码直接当成登录名，以免一家工厂只能有一个账号。

账期、币别、税率在门户上出现时，取值来自ERP或财务已经维护的资料。门户不维护第二套币别字典。展示ERP的单价、金额时，沿用ERP已确认的精度：单价4位小数，金额和税额2位小数。这是展示约束，不是门户自己的计价规则。门户不重算采购价格。

## 三、箱码

阶段4要求外箱码至少能对应采购订单、SKU、批次和数量。原调研只列了要承载的内容，没有规定码的结构。

建议分成两层，避免一改数量就要换码：

| 层 | 规则 | 未定事项 |
| --- | --- | --- |
| 标识 | 一箱一个唯一代码。国标GB/T 18127-2009规定物流单元用18位SSCC，和应用标识符AI(00)一起，以UCC/EAN-128表示。标准文本见[国家标准信息](https://std.samr.gov.cn/gb/search/gbDetailed?id=71F772D7CF01D3A7E05397BE0A0AB82A) | 强盛有没有GS1厂商识别代码，见【待确认-23】。没有的话先用内部唯一流水，并预留改成SSCC的位置。内部流水的具体长度未定 |
| 信息 | 采购订单、SKU、批次、数量、供应商不全部塞进条码图形，扫码后向门户或仓库查询 | 码制是一维还是二维、标签尺寸、贴在哪一面，必须和实际收货的PDA一起定，见【待确认-23】 |

和打印相关、已经能写死的限制：

- 同一发货行下，箱码数量之和等于该行发货数量。尾数单独成一箱，不并进整箱容量。
- 发货提交前可以删掉重打。提交之后，补打用原码并留下次数。贴错了要作废原码再生成新码，作废码不能再收。
- 内包装要不要第二级标签，见【待确认-23】。一期不能把「必须有小包码」写成已经确认。
- 一个箱子里放多种SKU是否允许，见【待确认-23】。未确认前按一箱一种SKU理解，避免和「箱码数量等于发货行数量」冲突。
- 东莞电商仓和FBA的箱唛有平台自己的规则，不纳入这套外箱码。它们是否还要另贴强盛的码，见【待确认-22】。

批次号是供应商给出的文本，先存在发货单和箱码上。它还不是ERP的库存批次，见[待对齐事项A13](11.待对齐事项.md)。

## 四、外部号码

| 号码 | 怎么存 |
| --- | --- |
| SRM采购订单号 | 源头单号。是否原样成为ERP单号，见【待确认-05】 |
| ERP采购订单号 | 若ERP另编，按原样保存，用作关联和去重，不改格式。同一SRM订单只保存一张ERP订单号 |
| 收货通知单号、入库单号、采退出库单号 | 按ERP原样保存，用作关联和去重，不改格式 |
| 数电票号码 | 20位。没有发票代码。纸质发票和旧版电子发票如果仍会出现，发票代码只作为兼容字段，不能当成数电票的必填。见[合规要求](8.合规与审计要求.md) |
| 运单号、车牌 | 普通文本，不参与门户单号 |

税票号码的查重范围是门户里已经登记的号码。税务平台上的真伪，不由号码格式校验代替，见【待确认-37】。

推送去重不靠「把失败的单号改掉再推一次」。失败的还是原来那张SRM订单。

## 五、不在本文规定的内容

- 各对象的字段清单、必填、长度和枚举。
- 导入模板。
- 箱码图片的分辨率和打印机型号。
- 把建议前缀写进条码的实施步骤。
- 重试次数和错误码。见【待确认-06】。

后续字段设计引用ERP主数据时，默认Code-Name。例外要写明原因。建议前缀在确认前，原型里的单号只是演示，不能回写成规则。
