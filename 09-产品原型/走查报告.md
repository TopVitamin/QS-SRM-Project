## 结论

主链路和硬约束是守住的：采购订单在 SRM 创建、审核、一张对一张推 ERP；ERP 副本只读；收货通知由模拟 ERP 生成再下发 WMS；入库只读回传；供应商改不了数量价格；不超发超收；不建应付；数电票 20 位、无发票代码；门店口径没有写成联营。设计说明第五节的 C01–C03、B01–B31、P01–P14 都有对应路由和可点页面。

没有「高」：供应商隔离、未下发订单对门户 404、代录仅限未开通门户、核对七项、24 小时不自动确认，接口层都挡住了。

**中 8、低 5。** 优先改模拟回传的角色范围、门户主数据裁剪、发货单推送失败仍可预约、预约角标口径，以及阶段 4/5 仓网混在同一下拉里。

## 已核对、不记为缺陷

### 页面

- C01 入口、C02 越权就地显示（`QueryState` 遇 403）、C03 其余路由 `NotFound` 都在。
- 工作台 B01–B31、门户 P01–P14 与 README 页面表一致。B14 代录发货有可发的 PY 订单（未开通门户、已代录确认、仍有本次可发）。
- 11.2 未做项保持未做，不当缺页。

### 主流程（采购订单在 SRM → 推 ERP → 再推 WMS）

- 只有采购员能 `createOrder`；审核通过后 `startOrderPush`；失败保留同一张 SRM 单，重推同一笔。
- ERP 副本在 `onPushAccepted` 写入，界面 `ErpReadonly`；变更只在 SRM 发起，`applyChange` 只在变更推送成功后改承诺交期。
- 发货不超过可下推：`lineQty` 为 采购数量 − 累计入库 − 在途通知，本次可发再减已提交未生成通知；超发、超收接口 409。
- `submitShipment` 先推 ERP 发货单；`simulateNotice` 要求 ERP 已接收（`waitingNotice`）；通知单状态直接 `issued`（已下发 WMS）；`simulateReceipt` 全收 / 缺量 / 零收，零收不生成入库单。
- 发货单 SRM 状态只有草稿 / 已提交 / 已取消，收货只看通知单和入库单。
- 下发时点「02」、未确认能否发货「19」、关闭发起方「04」走原型配置，默认：审核即下发、未确认不能发、关闭按钮置灰。

### 两端数据

- 工作台和门户读同一套 `/api` 和 `qs-srm-demo-db`。数量、确认状态、发货、预约、入库在两边同一条记录。
- 未下发（`notSent`）对供应商列表过滤、详情 404。企业侧发起的对账单草稿对供应商 404。
- 供应商不能改数量和价格；确认弹窗只有「按订单接单」；拒绝必须写原因。
- 超 24 小时只标红，不自动确认。

### 权限和隔离

- 供应商身份以门户账号档案为准，请求头里写别家编码无效。
- `assertScope`：改 URL 看别家单据 403，页面 C02。
- 代录只对 `portalStatus === '未开通'`；依据必填。
- 「34」打开后只收窄**采购员**的分管范围，仓储/财务仍看全部，与设计说明第七节一致。
- `GET /changes`、`GET /push-jobs`、`GET /kitting`、`GET /audit-logs`、`GET /performance`、`GET /alerts`、`GET /admissions` 对供应商 403。

### 口径（未编造强盛事实）

- 公司、SKU、价格、数量、日期均标示例数据；准入信用代码带 `SAMPLE`；地址、电话是示例号段。
- 供应商类别只列名称，不出现家数（「25」）。账期显示 `-`（「28」）。源码中无「联营」门店（A14）。
- 绩效页标明「口径草案」「不能进经营会」；切换「33」只用于对照；不排名、不出配额、不拦截下单。
- 税票号码 `/^\d{20}$/`，表单无发票代码。开票页写明应付、核销、付款在金蝶。
- 追溯链到金蝶节点只写「在金蝶」，不画假凭证。

## 问题清单

严重程度：**高** = 会写错业务或越权看到别家数据；**中** = 和已写明的规则/矩阵不一致，走查或演示会误导；**低** = 交互、演示简化或接口多带了字段，主路径仍对。

### 中

#### M1. 计划（只读）等非采购员企业角色能点模拟回传，改全库状态

| 项 | 内容 |
| --- | --- |
| 位置 | `src/mocks/shipments.ts` `shipmentActions.simulateNotice` / `simulateReceipt`（`isEnterprise`）；`src/mocks/finance.ts` `invoiceActions.usage`；`src/mocks/suppliers.ts` `admissionActions.simulateErpCreate`（`!isSupplierActor`）。页面：B13 发货详情、B16 收货结果「模拟ERP退货 / 模拟WMS退货出库」、B23「模拟用途确认」、B28「模拟ERP建档」 |
| 现象 | 设计说明第七节：计划「查看企业侧页面 ✓（只读）」。业务写操作（建单、审核、代录）已按 `hasRole('buyer')` 挡住。模拟回传却按「是不是企业侧」放行。切到计划、财务、品质、仓储、系统管理，仍可生成通知单、写入库、改税票用途确认、给准入回传 SUP 编码。这些按钮会 `commit` 同一份演示库，影响采购员和门户随后看到的状态。仓储确认预约是矩阵里的正权；仓储顺便「模拟 ERP 生成通知单」不是。 |
| 严重程度 | 中 |
| 修改建议 | 给模拟回传单独设能力，不要用 `isEnterprise` 一网打尽。建议：生成通知单 / 收货 / 退货默认仅采购员（演示主路径的人）；用途确认仅财务；ERP 建档仅采购员。计划、品质、系统管理隐藏。若有意让所有企业身份都能演，须在虚线框上写清「演示工具，不纳入第七节矩阵」，并让计划默认看不到，避免和「只读」打架。 |

#### M4. 发货单 ERP 推送失败后仍可预约送货

| 项 | 内容 |
| --- | --- |
| 位置 | `src/mocks/shipments.ts` `shipmentActions.appoint`：已提交且没有「已有收货结果」即可；不看 `shipmentErpStatus`。门户 P08、发货详情预约按钮 |
| 现象 | 生成通知单要求 `erpStatus === 'waitingNotice'`（ERP 已接收发货单）。预约没有这条。ERP 接口设为不可用、发货单推送失败时，供应商仍能约时段，仓储仍能确认。仓库确认的是一个 ERP 尚未接收、WMS 不会有采购收货通知单的车次。《3》§3.3 预约是收货预期，通知单才是执行指令；推送失败时放行预约，演示里会出现「车到了、账上没有通知单」。 |
| 严重程度 | 中 |
| 修改建议 | `appoint` 与 `simulateNotice` 对齐：仅 `waitingNotice` 或 `issued`（已下发、尚未最终结果）可约；`pushing` / `pushFailed` 置灰，原因写「ERP 还没接收这张发货单，先重推」。 |
